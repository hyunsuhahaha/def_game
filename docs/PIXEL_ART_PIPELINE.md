# 최우선: 모든 그래픽의 최소 품질 기준

**먼저 [GRAPHICS_STYLE_GUIDE.md](GRAPHICS_STYLE_GUIDE.md)를 읽고 실제 기준 이미지를 연다. 현재 카툰 픽셀 스타일은 숲뿐 아니라 앞으로의 모든 그래픽에 적용한다. 이 문서는 기술·품질 기준이며, 원하는 외형과 좋은 예/금지 예·대상별 적용·완료 체크리스트는 스타일 가이드를 따른다. “고밀도”를 실사나 장식적인 판타지 재디자인으로 해석하지 않는다.**

**사용자의 상시 지시: 앞으로 모든 그래픽은 아래 기준 이상의 고밀도 픽셀아트로 제작한다. 이 문서를 읽는 모든 AI와 이후 세션에 적용한다. 캐릭터에만 한정하지 않으며 장비·적·보스·배경·건물·아이콘·투사체·연기·불·기타 FX도 포함한다.**

- 재질 제작: [`cigarette-material.glsl`](../assets/shaders/cigarette-material.glsl).

- 연결·표시와 제작 기록: [`cigarette_sprite.lua`](../src/cigarette_sprite.lua), [`SMOKER_CIGARETTE_ART.md`](SMOKER_CIGARETTE_ART.md).

**비교 대상은 실제 픽셀 최종본이다. `smoker-cigarette-reference-v1.png`는 채택하지 않은 실사풍 콘셉트이며 품질 승인 예제가 아니다.**

| 평가 항목 | 기준과 적용 방법 |
|---|---|
| 원생 픽셀 정보량 | 기준 소품은 **256×48**, 불투명 픽셀 **70색**. 기존 4×2 조각을 확대한 것이 아니라 이 그리드에서 각 픽셀을 작성했다. 같은 종류·규모의 복합 재질 소품은 이 이상의 실제 세부 묘사를 확보한다. |
| 명암 그라데이션 | 기준은 **재질별 16단계 색상 램프 + 순서 디더링**. 광원 방향, 하이라이트, 중간톤, 그림자와 표면 곡률이 읽혀야 한다. 단색 면 몇 개를 그라데이션이라고 부르지 않는다. |
| 재질 구분 | 담배의 필터 기공·종이 섬유·이음선·재 조각·불씨처럼 대상에 맞는 세부 묘사가 서로 구분되어야 한다. 무작위 노이즈나 색 수 증가 자체는 디테일이 아니다. |
| 셰이더 | 제작용 셰이더로 픽셀 재질을 굽거나 런타임 셰이더로 고정 그리드 위 조명·발광·흐름을 표현한다. 재질의 형태를 존중하며, 큰 네모 발광이나 반투명 원 여러 개로 대체하지 않는다. |
| FX 밀도 | 연기 기준은 **192×384 / 월드 60×120**, 축당 **3.2 텍셀/월드 단위**. 최소한 이 밀도를 유지하며, 확대하면 해상도도 비례해서 늘린다. 예: 폭·높이 3배 → 그리드 축당 3배, 총 픽셀 수 9배. |
| 표시와 확대 | `nearest`로 고정 그리드를 유지한다. 실제 게임 크기에서도 대상·재질이 읽혀야 하고, 확대하면 의도적으로 작성된 미세 픽셀과 단계별 명암이 보여야 한다. 블러나 선형 보간으로 빈약한 원본을 숨기지 않는다. |
| 알파와 FX | 고체 스프라이트는 선명한 실루엣과 원칙적으로 이진 알파. 연기·빛은 고정 픽셀 그리드에서 단계화한 알파를 사용한다. 고체 전체에 흐릿한 반투명 테두리를 붙이지 않는다. |

숫자는 **관찰 가능한 품질 기준**이다. 모든 오브젝트를 담배와 같은 종횡비로 만들거나, 단순 색상 기호에 억지로 70색을 넣거나, 투명 여백으로 256×48만 맞추라는 뜻이 아니다. 대상의 크기·형태·재질에 맞춰 캔버스와 팔레트를 설계하되 **원생 픽셀 밀도, 재질별 명암, 실제 크기 가독성은 기준 이하로 낮추지 않는다.** 큰 캐릭터·건물·보스·배경은 그에 맞는 더 큰 제작 그리드와 세부 묘사가 필요하다.

## 금지되는 대체 방식

1. 4×2, 8×8, 16×16 등의 작은 그림을 늘려 놓고 고해상도 픽셀이라고 보고하기.
2. 실사풍 또는 매끈한 생성 원화를 그대로 쓰거나 단순 축소·양자화만 한 결과를 검수 없이 최종 픽셀아트로 채택하기.
3. 색 블록 몇 개, 사각형 불씨, 큰 원형 연기, 평면 도형 조합을 완성된 재질·FX로 취급하기.
4. 블러·보간·그라데이션 오버레이만으로 원본의 부족한 픽셀 묘사를 숨기기.
5. 테스트 통과, 파일 크기, 해상도 또는 색 수만으로 시각 품질을 승인하기.

## 모든 그래픽 작업의 완료 조건

1. 작업 전에 기준 자산과 관련 셰이더를 확인하고 대상의 제작 그리드·팔레트·표시 크기·필요 재질을 정한다.
2. 원본을 보존하고 버전이 있는 새 자산을 만든다. 캐릭터와 장비의 프레임·발선·입/손 앵커·좌우 방향·접촉 판정을 일치시킨다.
3. **실제 게임 표시 크기**와 **픽셀이 보이는 확대 뷰**를 모두 렌더해 눈으로 확인한다. 줌 변화에도 형태와 재질이 유지되는지 확인한다.
4. 크기·팔레트·투명도·런타임 연결·방향을 검사하고, 셰이더를 바꿨으면 오프스크린 GPU에서 실제 컴파일·렌더한다. 게임 창은 자동 실행하지 않는다.
5. 검증하지 못한 부분은 명확히 보고한다. 기준에 못 미치면 수정하며, 사용자의 명시적 허용 없이 저품질 대체안을 납품하지 않는다.

**FOR ALL AGENTS: This section is the mandatory visual quality floor for all graphics work. Native pixel detail, material-specific stepped shading, dithering and shader effects are required. A larger canvas or upscaled low-resolution image is not high-density pixel art. Validate both actual gameplay size and magnified pixels. Existing lower-quality assets are not precedents.**

아래는 기존 캐릭터의 호환 규격과 제작 절차다. 기존 아틀라스 크기는 자동 품질 승인 기준이 아니다. 새 작업에 해상도가 부족하면 원생 픽셀을 더 높은 그리드에 작성하고 버전별 프레임·앵커·런타임 매핑을 함께 갱신한다. 기존 파일을 단순 확대해 품질 기준을 충족했다고 주장하지 않는다.

# 고밀도 2D 픽셀 캐릭터 제작 파이프라인

## 목표

이 프로젝트의 캐릭터는 단순 축소 이미지나 프레임마다 인상이 달라지는 생성 이미지가 아니다. 고해상도 콘셉트의 정보량을 유지하면서 실제 게임 애니메이션에 필요한 실루엣, 발선, 장비 위치와 동작 타이밍을 고정한 고밀도 픽셀 스프라이트를 사용한다.

ImageGen과 픽셀 제작은 대체 관계가 아니다. ImageGen은 한 장의 정체성 기준 원화를 만드는 단계에 사용하고, 최종 애니메이션은 그 기준을 잠근 뒤 동일한 픽셀 규격에서 연속 동작으로 제작한다. 프레임마다 새 이미지를 생성하면 얼굴, 체형, 옷 주름, 장비와 조명이 흔들리므로 금지한다.

## 제작 순서

1. **정체성 원화 확정**: 체형, 얼굴, 복장, 주 장비, 재질, 대표 색과 실루엣을 한 장에서 확정한다.
2. **동작 설계**: 대기·걷기와 캐릭터 고유 액션의 준비, 접촉/방출, 회수 키포즈를 먼저 정한다.
3. **고정 그리드 배치**: 모든 프레임을 같은 `96 × 192 px` 셀과 `y=190` 발선에 배치한다. 발 아래 투명 여백과 지면 접점이 프레임마다 흔들리지 않아야 한다.
4. **캐릭터별 공통 팔레트**: 한 아틀라스 전체를 같은 72~110색 범위로 정리한다. 다른 캐릭터의 팔레트를 억지로 공유하지 않는다.
5. **픽셀 정리**: 알파를 단단하게 정리하고 단독 반투명 테두리, 색 번짐, 축소 복제 인물, 배경 잔여물을 제거한다. 얼굴·손·고유 장비는 실제 표시 크기에서 읽혀야 한다.
6. **장비·FX 분리**: 몸과 손의 운동은 시트에 넣는다. 장비는 시트 또는 별도 고밀도 장비 스프라이트를 사용하며 프레임별 입·손 앵커에 연결한다. 연기·불꽃·충격파·투사체·파편은 별도 런타임 FX로 둔다.
7. **판정 연결**: 피해, 발사, 채집과 자원 생성은 액션 애니메이션의 접촉/방출 프레임에서 한 번만 발생시킨다.
8. **헤드리스 검증**: 크기, 투명도, 프레임 누락, 발선, 팔레트와 런타임 경로를 스크립트로 검사한다. 게임 창은 자동 실행하지 않는다.

주요 캐릭터와 함께 보이는 중장비·나무·고유 스킬 FX도 실제 화면에 표시될 최종 픽셀 크기로 미리 굽는다. 1K 원화를 런타임에서 `nearest`로 수십 퍼센트 축소하는 방식은 픽셀 크기와 명암 단계가 캐릭터와 달라지므로 금지한다. 스킬 FX는 해당 캐릭터의 재질과 명도 범위에 맞춘 제한 팔레트 및 정수 좌표 픽셀 형태를 사용한다.

## 현재 아틀라스 계약

| 항목 | 규격 |
|---|---|
| 전체 크기 | `576 × 384 px` |
| 프레임 배열 | `6열 × 2행` |
| 셀 크기 | `96 × 192 px` |
| 1행 | 대기/걷기 6프레임 |
| 2행 | 고유 액션 6프레임 |
| 발선 | 셀 내부 `y=190` |
| 이미지 | 투명 RGBA PNG |
| 런타임 필터 | `nearest` |
| 표시 배율 | 현재 `0.61` |

방향 전환은 캐릭터가 바라보는 월드 방향을 기준으로 시트를 좌우 반전한다. 손의 장비, 입의 담배, 투사체 방출점과 별도 FX도 같은 방향 기준을 공유해야 한다.

## 캐릭터별 액션 기준

- **생계형 나무꾼**: 도끼를 들어 올리는 준비 → 몸통 회전 → 날의 접촉 → 반동 → 회수. 나무 피해와 파편은 날이 목표에 닿는 프레임에 발생한다.
- **흡연자**: 담배는 대기·걷기 중에도 바라보는 방향의 입에 계속 물려 있다. 흡연은 재장전 상태이고 공격 입력 시 새로 담배를 무는 것이 아니라 손가락으로 꽁초를 튕긴다. 버튼을 누르고 있으면 재장전이 끝날 때마다 다음 투척 모션을 자동으로 시작하되, 투사체는 각 모션의 손가락에서 놓이는 프레임에 한 번만 생성한다.
- **비건 단체 회장**: 짧은 다리와 넓은 허리의 중년 여성 실루엣을 유지한다. 별도 `256×96` 네 갈래 포크를 손 앵커에 붙이고, 몸을 크게 숙이는 준비 → 전방 다중 찌르기 → 접촉 → 회수 순서를 사용한다. 화면 축소 시에도 포크 끝과 전방 판정이 겹쳐 보여야 한다. 치명타가 아니라 **포크로 HP를 0으로 만든 나무와 적만** 실제 실루엣을 유지한 채 입 쪽으로 끌어당겨 먹는 연출을 재생한다. 독·감염 표현은 이 캐릭터의 시각 언어로 사용하지 않는다.
- **비건 단체 회장**: 식물/나뭇가지를 낚아채는 준비 → 당김 → 물어뜯기/섭취 → 회수. 피해와 흡수는 물어뜯는 접촉 프레임에 연결한다.
- **부동산 개발업자**: 리모컨·도면 지시 → 중장비 호출/돌진 → 철거 접촉 → 확인/회수. 중장비 충돌 판정과 지면 파편은 실제 접촉 프레임을 따른다.

## 금지 사항

- 애니메이션 프레임마다 ImageGen으로 캐릭터를 새로 생성하기
- 캐릭터 몸, 손, 담배나 도끼 같은 핵심 장비를 원·선·사각형 런타임 드로잉으로 대신하기
- 카테고리별로 흰색·노랑 등 하나의 색 체계를 강제하기
- 발선, 인물 크기, 얼굴 방향과 광원을 프레임마다 바꾸기
- 불투명 배경이나 지면을 캐릭터 PNG에 굽기
- 타격 이펙트와 피해를 액션과 무관한 반복 타이머로 발생시키기
- 이전 원본과 초안을 새 결과로 덮어쓰기

## 빌드와 검사

현재 4종은 고정된 고해상도 원본 아틀라스를 입력으로 사용하고, 공통 빌더가 셀·발선·팔레트·알파 계약을 적용한다.

```powershell
python scripts/build_character_pixel_atlas.py logger assets/characters/ingame/logger-atlas-v1.png assets/characters/ingame/logger-atlas-pixel-v2.png
python scripts/build_character_pixel_atlas.py smoker assets/characters/ingame/smoker-atlas-v1.png assets/characters/ingame/smoker-atlas-pixel-v2.png
python scripts/build_character_pixel_atlas.py vegan assets/characters/ingame/vegan-atlas-v1.png assets/characters/ingame/vegan-atlas-pixel-v2.png
python scripts/build_character_pixel_atlas.py developer assets/characters/ingame/developer-atlas-v1.png assets/characters/ingame/developer-atlas-pixel-v2.png
python scripts/verify_character_pixel_atlases.py
python scripts/verify_smoker_pixel_atlas.py
```

`scripts/build_character_pixel_atlas.py`가 현재 정식 빌더다. 자동 변환 결과도 눈으로 검수해야 하며, 얼굴·손·장비가 읽히지 않거나 원본 프레임이 오염된 경우 해당 프레임을 수작업 교정한 뒤 다시 검사한다.
